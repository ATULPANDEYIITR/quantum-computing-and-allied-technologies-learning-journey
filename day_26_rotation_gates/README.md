# Rotation Gates: RX, RY, RZ

## Topic Introduction

Single-qubit rotation gates are fundamental operations in quantum computing. `RX`, `RY`, and `RZ` describe rotations of a qubit around the three Cartesian axes of the Bloch sphere.

The three gates are defined by the Pauli matrices:

- `X` generates rotation around the x-axis.
- `Y` generates rotation around the y-axis.
- `Z` generates rotation around the z-axis.

Their general form is:

`R_axis(theta) = exp(-i theta sigma_axis / 2)`

where `theta` is the rotation angle and `sigma_axis` is the corresponding Pauli operator.

The three gates are:

`RX(theta) = exp(-i theta X / 2)`

`RY(theta) = exp(-i theta Y / 2)`

`RZ(theta) = exp(-i theta Z / 2)`

These operations are unitary, preserve quantum-state normalization, and can be composed to construct arbitrary single-qubit transformations up to a global phase.

---

## 1. Qubit Fundamentals

A pure single-qubit state is written as:

`|psi> = alpha|0> + beta|1>`

where `alpha` and `beta` are complex probability amplitudes.

The computational basis consists of:

- `|0> = [1, 0]^T`
- `|1> = [0, 1]^T`

The amplitudes must satisfy the normalization rule:

`|alpha|^2 + |beta|^2 = 1`

The quantities `|alpha|^2` and `|beta|^2` are the probabilities of obtaining `0` and `1` when the qubit is measured in the computational basis.

The Python implementation represents this concept through the `QubitState` class. The JavaScript implementation uses a `Qubit` class, while the C++ case study uses `QubitState`.

Each implementation validates normalization rather than assuming that incoming state vectors are correct.

---

## 2. Complex Amplitudes

Quantum states require complex numbers because quantum interference depends on both amplitude magnitude and phase.

A complex number can be written as:

`z = a + ib`

where:

- `a` is the real component.
- `b` is the imaginary component.
- `i` is the imaginary unit satisfying `i^2 = -1`.

The Python implementation uses Python's built-in `complex` type.

The JavaScript implementation creates explicit objects with `real` and `imaginary` properties because JavaScript does not provide a native general-purpose complex-number type.

The C++ implementation uses `std::complex<double>` from the standard library.

This difference is technically important. Python and C++ provide direct language/library support for complex arithmetic, while JavaScript requires a representation and helper functions for complex addition, multiplication, conjugation, magnitude, and exponential phase.

---

## 3. Why Rotations Use Half Angles

The matrices contain `theta / 2`, not `theta`.

For example:

`RX(theta) = [ cos(theta/2), -i sin(theta/2); -i sin(theta/2), cos(theta/2) ]`

The same half-angle structure occurs in `RY` and `RZ`.

This is a consequence of the spin-1/2 representation of quantum states. A qubit's unitary rotation is generated by a Pauli operator with a factor of one-half:

`R_axis(theta) = exp(-i theta sigma_axis / 2)`

The corresponding Bloch vector undergoes an ordinary geometric rotation by `theta`.

The distinction between the unitary's half-angle and the Bloch sphere's full rotation angle is one of the most important details when implementing these gates.

---

## 4. RX Gate

The `RX` gate rotates a qubit around the x-axis.

Its matrix is:

`RX(theta) = [ cos(theta/2), -i sin(theta/2); -i sin(theta/2), cos(theta/2) ]`

For the computational basis state `|0>`:

`RX(theta)|0> = cos(theta/2)|0> - i sin(theta/2)|1>`

Therefore:

`P(0) = cos^2(theta/2)`

`P(1) = sin^2(theta/2)`

at the level of computational-basis probabilities for this particular input.

### Important special cases

For `theta = 0`:

`RX(0) = I`

For `theta = pi`:

`RX(pi)|0> = -i|1>`

The `-i` factor is a global phase for this isolated state and does not alter measurement probabilities.

For `theta = 2pi`, the unitary matrix is `-I`. This illustrates an important distinction between the mathematical state-vector transformation and the physical Bloch-sphere rotation. A `2pi` Bloch-sphere rotation returns the Bloch vector to its original position, while the spinor state acquires a global minus sign.

The Python and C++ programs demonstrate these properties through explicit matrix construction and state application.

---

## 5. RY Gate

The `RY` gate rotates around the y-axis.

Its matrix is:

`RY(theta) = [ cos(theta/2), -sin(theta/2); sin(theta/2), cos(theta/2) ]`

Applying it to `|0>` gives:

`RY(theta)|0> = cos(theta/2)|0> + sin(theta/2)|1>`

Consequently:

`P(0) = cos^2(theta/2)`

`P(1) = sin^2(theta/2)`

This makes `RY` particularly useful for simple single-qubit state preparation when real-valued amplitudes are sufficient.

For example:

`RY(pi/2)|0> = (|0> + |1>) / sqrt(2)`

which is the `|+>` state.

For:

`theta = pi`

the transformation maps `|0>` to `|1>`.

The Python, JavaScript, and C++ implementations all demonstrate `RY` as a probability-control operation.

---

## 6. RZ Gate

The `RZ` gate rotates around the z-axis.

Its matrix is:

`RZ(theta) = [ exp(-i theta/2), 0; 0, exp(i theta/2) ]`

Applying it to a general state gives:

`RZ(theta)(alpha|0> + beta|1>)`

`= alpha exp(-i theta/2)|0> + beta exp(i theta/2)|1>`

The magnitudes of both amplitudes remain unchanged.

Therefore computational-basis probabilities remain unchanged:

`P(0)' = P(0)`

`P(1)' = P(1)`

But the relative phase changes.

The relative phase contribution between the two basis components changes by `theta`.

This distinction is essential:

- RZ does not directly alter computational-basis populations.
- RZ changes relative phase.
- Relative phase can affect subsequent interference.
- Therefore RZ can have measurable effects after other gates are applied.

The implementations demonstrate this by applying `RZ` to `|0>` and to `|+>`.

## 8. Unitary Property

A valid ideal quantum gate is represented by a unitary matrix.

A matrix `U` is unitary when:

`U†U = I`

where `U†` is the conjugate transpose.

Unitarity implies that quantum-state normalization is preserved.

The three rotation gates satisfy:

`RX(theta)† RX(theta) = I`

`RY(theta)† RY(theta) = I`

`RZ(theta)† RZ(theta) = I`

All three implementations explicitly test unitarity.

This is also an important implementation validation technique. If a supposedly ideal rotation matrix fails the unitarity test beyond numerical tolerance, there is likely an implementation error.

---

## 9. Applying a Rotation to a State

Given:

`|psi> = [alpha, beta]^T`

and a gate:

`U = [u00, u01; u10, u11]`

the transformed state is:

`U|psi>`

which gives:

`alpha' = u00 alpha + u01 beta`

`beta' = u10 alpha + u11 beta`

The implementations perform this matrix-vector multiplication directly.

The resulting vector is normalized again to protect against small floating-point errors.

In an exact mathematical calculation, a unitary matrix preserves normalization exactly. In finite-precision software, very small numerical deviations can occur.

---

## 10. Bloch Sphere

A pure qubit can be represented geometrically by a point on the Bloch sphere.

For:

`|psi> = alpha|0> + beta|1>`

the Bloch coordinates are:

`x = 2 Re(alpha* beta)`

`y = 2 Im(alpha* beta)`

`z = |alpha|^2 - |beta|^2`

where `alpha*` denotes the complex conjugate of `alpha`.

The computational basis states correspond to:

- `|0>` -> north pole `(0, 0, 1)`
- `|1>` -> south pole `(0, 0, -1)`

The `|+>` state is located on the positive x-axis:

`|+> -> (1, 0, 0)`

The `|->` state is on the negative x-axis:

`|-> -> (-1, 0, 0)`

The state:

`|+i> = (|0> + i|1>) / sqrt(2)`

lies on the positive y-axis.

The Python, JavaScript, and C++ implementations calculate Bloch coordinates directly from state amplitudes.

---

## 11. RX, RY, RZ as Bloch-Sphere Rotations

The geometric interpretation is:

- `RX(theta)` rotates the Bloch vector around the x-axis.
- `RY(theta)` rotates the Bloch vector around the y-axis.
- `RZ(theta)` rotates the Bloch vector around the z-axis.

This provides a useful conceptual distinction between the gates.

`RX` and `RY` generally change the z-coordinate and therefore can change computational-basis measurement probabilities.

`RZ` preserves the z-coordinate while changing the azimuthal orientation of the state.

The Bloch representation is particularly useful for visualizing single-qubit control.

---

## 12. Global Phase

Multiplying a state by a phase:

`|psi'> = exp(i gamma)|psi>`

produces a global phase.

For example:

`|psi'> = exp(i gamma)(alpha|0> + beta|1>)`

The global phase does not affect measurement probabilities or the physical pure-state ray.

This is why:

`|psi>`

and

`exp(i gamma)|psi>`

have fidelity equal to one.

The implementations include state-fidelity calculations that recognize this physical equivalence.

---

## 13. Relative Phase

Relative phase is different from global phase.

Suppose:

`|psi> = alpha|0> + beta|1>`

The phase difference between the two amplitudes can affect interference.

An RZ rotation applies opposite phase shifts to the two basis states:

`|0> -> exp(-i theta/2)|0>`

`|1> -> exp(i theta/2)|1>`

The relative phase therefore changes by `theta`.

This is why an RZ operation can have no immediate effect on computational-basis probabilities but can change the result of later operations.

This behavior is central to understanding quantum interference.

---

## 14. Measurement

The Born rule determines computational-basis probabilities:

`P(0) = |alpha|^2`

`P(1) = |beta|^2`

The implementations include shot-based measurement simulation.

For a state with `P(0) = 0.75`, repeated measurements do not necessarily produce exactly 75% zeros in a finite experiment. Instead, the empirical proportion fluctuates around the theoretical probability.

The Python and JavaScript examples use deterministic seeds for reproducible educational output.

The C++ example uses `std::mt19937` and a fixed seed.

Real quantum hardware has additional sources of error that are not modeled by this ideal simulator, including readout error and physical noise.

---

## 15. Rotation Composition

Sequential gates are represented by matrix multiplication.

If a state is transformed by:

`G1`

and then:

`G2`

the final state is:

`G2 G1 |psi>`

The rightmost operation acts first.

This ordering is essential when reasoning about quantum circuits.

For example:

`RY(beta) RX(alpha)`

means:

1. Apply `RX(alpha)`.
2. Apply `RY(beta)`.

It does not mean the reverse.

The circuit implementations explicitly construct the combined unitary using this ordering.

---

## 16. Same-Axis Rotations

Rotations around the same axis satisfy:

`RX(a)RX(b) = RX(a+b)`

Similarly:

`RY(a)RY(b) = RY(a+b)`

and:

`RZ(a)RZ(b) = RZ(a+b)`

This property is useful for circuit simplification.

For example:

`RY(0.2) -> RY(0.3)`

can be replaced by:

`RY(0.5)`

without changing the ideal mathematical transformation.

The C++ case study includes an optimizer that combines consecutive rotations around the same axis.

It verifies the optimization by comparing the resulting combined unitaries.

---

## 17. Different-Axis Rotations Are Generally Non-Commutative

In general:

`RX(a)RY(b) != RY(b)RX(a)`

Likewise:

`RX(a)RZ(b) != RZ(b)RX(a)`

and:

`RY(a)RZ(b) != RZ(b)RY(a)`

This is a fundamental property of quantum operations.

The order of operations therefore cannot normally be rearranged for convenience.

The three implementations demonstrate different gate orders and compare the resulting states using fidelity.

---

## 18. Inverse Rotations

The inverse of a rotation is obtained by negating its angle:

`RX(theta)† = RX(-theta)`

`RY(theta)† = RY(-theta)`

`RZ(theta)† = RZ(-theta)`

Therefore:

`RX(theta)RX(-theta) = I`

and equivalent identities hold for RY and RZ.

This is useful for:

- reversing a circuit operation;
- constructing uncomputation sequences;
- validating gate implementations;
- simplifying circuits;
- debugging state transformations.

The implementations explicitly apply a rotation and its inverse and verify that the original state is recovered up to numerical precision.

---

## 19. Periodicity

At the Bloch-sphere level, rotations are periodic with a period of `2pi`.

For example:

`R_axis(theta + 2pi)`

produces the same Bloch-vector orientation as:

`R_axis(theta)`

But qubit state vectors contain an important spinor property.

For a `2pi` rotation:

`R_axis(2pi) = -I`

For a `4pi` rotation:

`R_axis(4pi) = I`

The `-1` after a `2pi` rotation is a global phase for an isolated pure state, so it does not alter ordinary measurement probabilities. It is still important mathematically and can matter when analyzing coherent transformations and relative phases in larger systems.

---

## 20. Arbitrary-Axis Rotation

RX, RY, and RZ rotate around the Cartesian axes.

A general rotation can be performed around a normalized axis:

`n = (nx, ny, nz)`

with:

`nx^2 + ny^2 + nz^2 = 1`

The corresponding unitary is:

`R_n(theta) = exp(-i theta (nx X + ny Y + nz Z) / 2)`

Using the Pauli algebra, the closed form is:

`R_n(theta) = cos(theta/2)I - i sin(theta/2)(nx X + ny Y + nz Z)`

The Python, JavaScript, and C++ implementations include arbitrary-axis rotation functions.

The zero vector is rejected because it cannot define a rotation axis.

---

## 21. Euler-Angle Decomposition

Single-qubit unitary transformations can be decomposed into rotations around coordinate axes.

A common form is:

`U = RZ(phi) RY(theta) RZ(lambda)`

up to a possible global phase depending on the unitary convention.

This is important because a general single-qubit operation does not require an entirely new primitive for every possible transformation. A sufficiently expressive set of parameterized rotations can represent the required transformation.

The Python implementation contains a `u3` function that constructs a Z-Y-Z decomposition.

---

## 22. Parameterized Gates

RX, RY, and RZ are parameterized gates.

The parameter is a continuous angle:

`theta in R`

This allows them to represent families of transformations rather than one fixed transformation.

Parameterized gates are important in:

- variational quantum algorithms;
- quantum machine learning;
- quantum optimal control;
- calibration;
- parameterized quantum circuits;
- state preparation;
- circuit optimization.

The Python circuit class, JavaScript circuit class, and C++ control circuit all store gate angles explicitly.

## 27. Numerical Precision

Quantum simulators commonly use floating-point arithmetic.

Expressions that are mathematically equal may differ by tiny numerical errors.

For example:

`RX(theta)RX(-theta)`

should mathematically equal identity, but a floating-point implementation may produce entries differing from the exact result by values around machine precision.

Therefore code should not normally use:

`computed == expected`

for floating-point quantum-state comparisons.

Tolerance-based comparisons are more appropriate.

The implementations use matrix norms and fidelity thresholds.

`0 <= F <= 1`

- smaller values indicate increasing distinguishability.

Fidelity is useful for validating:

- optimized circuits;

- gate decompositions;

## 30. Edge Cases

Important edge cases include:

### Zero rotation

`R_axis(0) = I`

### Very large angles

Angles may be reduced or wrapped numerically when appropriate.

### Negative angles

Negative angles represent inverse-direction rotations.

### Zero rotation axis

An arbitrary-axis rotation cannot use:

`(0, 0, 0)`

because it cannot be normalized.

### Unnormalized state

A valid pure-qubit state must satisfy:

`|alpha|^2 + |beta|^2 = 1`

### Undefined relative phase

If either amplitude is zero, the phase of that zero amplitude is not defined, so a relative-phase calculation based directly on the two amplitude arguments is not meaningful.

### Zero measurement shots

A measurement simulation requires a positive number of shots.

The implementations explicitly reject these invalid cases.

## 31. Common Mistakes

### Mistake 1: Forgetting the half angle

Incorrect:

`cos(theta)`

inside the rotation matrix.

Correct:

`cos(theta/2)`

and:

`sin(theta/2)`.

### Mistake 2: Treating RZ as a probability-changing gate

RZ changes phase rather than directly changing computational-basis populations.

Its effect becomes visible through later interference.

### Mistake 3: Reordering gates

In general:

`AB != BA`

for quantum rotation matrices involving different axes.

### Mistake 4: Ignoring complex numbers

RX and RZ naturally introduce complex phases.

A real-only representation cannot correctly model arbitrary single-qubit rotation behavior.

### Mistake 5: Using exact floating-point equality

Small numerical errors are expected.

Use tolerances or fidelity.

### Mistake 6: Confusing global and relative phase

A global phase does not change a pure state's physical predictions by itself.

Relative phase can change interference.

### Mistake 7: Assuming a Bloch-sphere return means the state vector is identical

A `2pi` spinor rotation produces a minus sign:

`R_axis(2pi) = -I`

The Bloch vector is unchanged, but the state vector acquires a global phase.

## 32. Performance Considerations

For a single qubit, the state vector has only two complex amplitudes, so the computation is effectively constant-sized.

A 2x2 matrix multiplied by a two-element vector requires a fixed number of operations.

For an n-qubit state-vector simulator, the state contains:

`2^n`

complex amplitudes.

Therefore:

- state-vector memory is `O(2^n)`;
- applying a one-qubit gate to a full state vector is typically `O(2^n)`.

This exponential scaling is a major limitation of direct classical state-vector simulation.

The C++ implementation uses fixed-size arrays and the standard library, avoiding unnecessary dynamic structures for the mathematical core.

The Python implementation prioritizes readability and educational transparency.

The JavaScript implementation prioritizes application-level representation and asynchronous experiment patterns.

---

## 33. Circuit Optimization

Same-axis consecutive rotations can be combined.

For example:

`RX(a) RX(b)`

can become:

`RX(a+b)`

This can reduce the number of operations.

Such an optimization is safe because the generators are the same.

It is not generally valid to combine different axes using simple angle addition.

For example, this is not generally valid:

`RX(a) RY(b) = RZ(a+b)`

There is no such general identity.

More advanced circuit compilation uses algebraic identities, matrix decompositions, hardware-native gate sets, pulse constraints, and optimization algorithms.

## 37. Important Distinctions

### RX versus RY

Both can change computational-basis probabilities when applied to suitable states, but they introduce different phase structures and rotate around different Bloch-sphere axes.

### RY versus RZ

RY can change the population distribution of `|0>` and `|1>`.

RZ preserves computational-basis populations while changing relative phase.

### RX versus RZ

RX mixes basis amplitudes with complex coefficients.

RZ applies opposite phase rotations to the basis components.

### Same-axis versus different-axis composition

Same-axis rotations can be combined by adding angles.

Different-axis rotations generally cannot.

### Mathematical gate versus physical pulse

A mathematical rotation specifies an ideal unitary.

A physical implementation requires hardware control parameters that approximate that unitary.

## 38. Design Principles Demonstrated

The implementations use several software-design principles relevant to quantum programming.

### Separation of concerns

Gate construction, state representation, measurement, circuit management, and validation are separate components.

### Explicit mathematical representation

Matrices are constructed directly so the relationship between equations and implementation remains visible.

### Validation at boundaries

Invalid states, invalid rotation axes, invalid shot counts, and non-unitary matrices are rejected.

### Immutable-style state transitions

Applying a gate returns a new state rather than modifying the existing state in place.

This makes circuit reasoning easier and reduces accidental state mutation.

### Reproducible experiments

Fixed random seeds allow measurement demonstrations to be repeated consistently.

### Automated verification

Self-tests verify fundamental mathematical identities.

## 41. Core Formula Reference

### RX

`RX(theta) = exp(-i theta X / 2)`

`RX(theta) = [ cos(theta/2), -i sin(theta/2); -i sin(theta/2), cos(theta/2) ]`

### RY

`RY(theta) = exp(-i theta Y / 2)`

`RY(theta) = [ cos(theta/2), -sin(theta/2); sin(theta/2), cos(theta/2) ]`

### RZ

`RZ(theta) = exp(-i theta Z / 2)`

`RZ(theta) = [ exp(-i theta/2), 0; 0, exp(i theta/2) ]`

### State

`|psi> = alpha|0> + beta|1>`

### Normalization

`|alpha|^2 + |beta|^2 = 1`

### Measurement

`P(0) = |alpha|^2`

`P(1) = |beta|^2`

### Bloch vector

`x = 2 Re(alpha* beta)`

`y = 2 Im(alpha* beta)`

`z = |alpha|^2 - |beta|^2`

### General axis

`R_n(theta) = exp(-i theta (n . sigma) / 2)`

### Inverse

`R_axis(theta)† = R_axis(-theta)`

### Same-axis composition

`R_axis(a)R_axis(b) = R_axis(a+b)`

### Fidelity

`F = |<psi|phi>|^2`

## 42. Execution

The Python file can be executed with a standard Python 3 installation.

The JavaScript file can be executed in a modern JavaScript runtime such as Node.js.

The C++ program is designed for C++17 or later.

No external quantum-computing package is required by any of the three implementations. The purpose is to expose the underlying mathematics, state representation, matrix operations, circuit ordering, measurement model, and implementation considerations directly.

The examples are deliberately limited to a single qubit so that the relationship between equations, matrices, state vectors, Bloch geometry, and executable code remains explicit.
